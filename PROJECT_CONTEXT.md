## Мышь и объёмные виды: 1.11.0

Пользователь сообщил о рывках мыши в первом и третьем лице; видом сверху доволен. Переработаны `Turning.cs` и новый `MouseMotion.cs`: стандартный Raw Input пакет плюс пакетное чтение накопившейся очереди, дополнительное чтение перед кадром, запрет дублирующих legacy-сообщений при захвате. Абсолютные устройства обрабатываются напрямую с отдельной исходной точкой для каждого устройства; первый пакет не вращает камеру, постоянного перецентрирования нет. При освобождении мыши накопленные движения сбрасываются. ClipCursor обновляется только при изменении границ/сбросе Windows. Для WOW64 сохранён стандартный способ чтения ввода вместо неподтверждённого буферного формата.

Базовая чувствительность снижена: 0,002 радиана на отсчёт по обеим осям. В настройках есть три уровня `.55 / 1 / 1.7`, поле `Settings.MouseSensitivity`; выбор сохраняется, старые настройки получают 1. Размер окна больше не меняет чувствительность запасного legacy-ввода. Дополнительное запаздывающее сглаживание не добавлялось.

Новые `MouseTests.cs` проверяют сохранение отсчётов при 125–8000 Гц и 60/120/170 FPS, абсолютные координаты, смену устройств и очистку движения. Всего 964 проверки логики. Native pointer-тест проверяет реальные регистрацию/курсор и синтетические пакеты того же формата, но не физическую мышь на 8000 Гц.

`--motion-test` (новый `MotionTest.cs`) вращает оба объёмных вида в полноэкранном режиме с синтетическими потоками 1000 и 8000 Гц по 6 секунд, сохраняет `motion-test-results.txt`: FPS, median/p95/p99/max интервалов. Тест изолирован от посторонних legacy-событий и проверяет, что камера получила заданный поворот; пауза/потеря управления делают прогон неуспешным. В коротких прогонах — примерно 154–168 FPS, p95 обычно менее 8 мс. Единичная стартовая задержка ~34–41 мс сохранялась: не обещать полного отсутствия лагов. Если пользователь снова заметит проблему, потребуется уточнить тип/настройки физической мыши и конкретный сценарий, а не ориентироваться только на средний FPS неподвижной камеры.

Проверено обновление 1.10.1 → 1.11.0 с изолированным AppId. Отчёт финальных проверок — `docs/VALIDATION.md`. Полный ручной проход с физической мышью не выполнялся; вид сверху и игровая логика сохранены.

## Что уже умеет игра

- Мягкая пиксельная графика: персонаж, машины, окружение. **Весь текст сглаженный**, Segoe UI, рисуется в разрешении окна отдельно от пиксельного кадра 480 × 320.
- Главное меню, настройки, пауза, карта, поражение и победа. Три камеры: сверху, от первого и от третьего лица.
- WASD — движение; мышь без ПКМ поворачивает персонажа и вертикальный взгляд; Q/E временно поворачивают голову, не меняя направление движения. V меняет камеру, M — карта, Esc — пауза, Tab освобождает/захватывает мышь. Raw Input; курсор освобождается в меню, на карте и при потере фокуса.
- Длинный маршрут А → Б: 12 районов, 360 дорог, короткие промежутки между ними. Теоретический минимум по расстоянию — 21:00,25, автоматический размеченный проход без машин со светофорами — примерно 29 минут. Нельзя пропускать порядок отметок.
- Пронумерованные отметки — контрольные точки **текущего забега**. После столкновения кнопка повтора / R возвращает к последней отметке; до первой — к А. Время, прогресс и транспорт сохраняются. Новая игра из меню начинается с А. Сохранения маршрута между запусками нет.
- На дороге нельзя полностью уходить вбок с зебры. Частичное пересечение/касание боковой границы разрешено. Полный выход возвращает к контрольной точке и открывает окно **«За зебру выходить нельзя»**. Оно объясняет правило, останавливает игру и освобождает курсор до кнопки «Понятно — продолжить», Enter, пробела или Esc. На тротуарах ходьба свободная.
- 19 видов транспорта: легковые, такси, автобус, грузовики/фура/самосвал, полиция, скорая, пожарные, дорожная служба, эвакуатор, велосипедист, мотоциклист; президентский кортеж из пяти машин с охраной и лимузином. Разные габариты, скорость, окраска, маячки; очереди и дистанция.
- Ровно 18 из 360 переходов (5%) со светофорами и отдельной безопасной пешеходной фазой. На красный игрок ждёт у бордюра без поражения; уже начатый переход можно закончить. Подробности фаз — в `TrafficSignals.cs` и README.
- Полный экран без рамки по умолчанию. F11 / Alt+Enter и настройки переключают оконный режим; обычный размер окна хранится отдельно. Масштабирование сохраняет пропорции, по бокам широких экранов остаются поля.

## Последнее изменение: автоматический FPS, версия 1.10.0

- Удалён фиксированный предел 60 FPS. Цель совпадает с **текущей частотой выбранного экрана в Windows**, не с максимальным режимом из списка поддерживаемых. Настройки Windows игра не меняет.
- `EnumDisplaySettingsExW` читает частоту монитора, на котором расположено окно. Перечитывание при перемещении, `WM_DISPLAYCHANGE` и примерно раз в секунду. Неизвестная частота 0/1 → запасные 60 FPS. Полноэкранные границы также подстраиваются под экран.
- `FramePump` использует отдельный поток и высокоточный waitable timer, с запасным ожиданием для старых Windows 10. Только один запрос кадра в очереди; устаревшие сроки пропускаются. Симуляция и рисование остаются в UI-потоке. Мышь обновляет угол без внеплановой перерисовки на каждое событие.
- Вывод: переиспользуемый нативный DIB-буфер, быстрое масштабирование строк, один BitBlt готового кадра. Шрифты кешируются; скрытые грани объёмных коробок не рисуются. В сборке нужен `/unsafe+` — уже включён в `Build.bat`.
- Индикатор `FPS X / Y` показывает фактическую частоту и цель, ниже — герцы монитора. Это цель, не обещание постоянного FPS при любой нагрузке; синхронизация VSync/VRR отдельно не реализована.
- Исправлен сброс системного ограничения курсора после переключения полного экрана: `SyncMouseLook` восстанавливает актуальные границы при активном захвате.

## Сборка, данные и публикация

- C# / WinForms, .NET Framework 4.8, без внешних библиотек. PowerShell, рабочая папка `D:\ProjectGPT\пиксельный переход Игра`.
- `cmd /c Build.bat` собирает `пиксельный переход Игра.exe` встроенным `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`.
- `cmd /c BuildInstaller.bat` собирает EXE и установщик; Inno Setup: `C:\Program Files (x86)\Inno Setup 6\ISCC.exe`. Исходник — `installer/QuietCrossing.iss`.
- Согласованно менять версию в `AssemblyInfo.cs`, меню, `.iss`, README и `tools/PublishRelease.ps1`. Выпуски лежат в игнорируемом `installer-output`.
- Проверки запускать через `Start-Process -Wait -PassThru`, проверяя ExitCode. `--ui-test` пересоздаёт снимки в `docs`; `--display-test` измеряет реальный цикл и перенос между экранами. `--benchmark` измеряет рендер отдельно от вывода на монитор. Текстовые результаты тестов игнорируются Git.
- Пользовательские настройки: `%LOCALAPPDATA%\QuietCrossing\settings.xml`. Сохранять их и совместимость. Не запускать обычную пользовательскую игру ради тестов; тестовые режимы используют отдельные настройки в памяти.
- `.installer-test` — игнорируемые изолированные установочные проверки. Не запускать настоящий установщик с production AppId в тестовую папку: для тестов менялись AppId и имена ярлыков. Не трогать рабочую установку и данные пользователя.
- Постоянные правила пользователя: по завершении изменений проверять, коммитить и отправлять на GitHub; при изменении приложения пересобирать EXE/установщик и публиковать GitHub Release; проверять публичное скачивание. Для одного файла документации пересборка приложения и новый релиз не нужны.
- GitHub: аккаунт MaksimDenisov31, remote уже настроен. Credential helper `manager`; GitHub CLI отсутствовал. Существующая авторизация Git/GCM работает, не просить подключать заново без фактической проверки.
- `tools/PublishRelease.ps1 -Release` получает авторизацию из `git credential fill` только в памяти процесса и загружает установщик, ZIP и SHA256SUMS через GitHub REST API. Никогда не выводить учётные данные и не сохранять их в файлы.
- Публикация: сначала коммит/push, затем подготовленные ZIP/установщик/контрольные суммы и Release. Сетевой сбой TLS уже встречался; повтор через `[Net.ServicePointManager]::SecurityProtocol=[Net.SecurityProtocolType]::Tls12` сработал. Сетевую ошибку не выдавать за отсутствие авторизации.
- Установочным тестам и сетевым операциям в этой среде требовался запуск вне ограничения sandbox; это не отсутствие прав GitHub. Не завершать принудительно пользовательские приложения.
